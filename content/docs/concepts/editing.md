## Example and expected outcome

Use the [full transcript](/concepts/project-kickoff-v1/transcript.json); PK identifiers are stable, not API commands. A selection describes the intended target. A command requests an operation against the current document and permissions. An accepted content change, a selection update and a save are separate observations.

| Steps | Input/action | Independently expected meaning |
| --- | --- | --- |
| PK-02 | Select Friday in `Due Friday` | Content remains `kickoff-v1`; only selection changes. |
| PK-03 | Remove bold from Friday | `friday-plain-v1`: same words, Friday has no bold mark. |
| PK-04 | Apply bold to Friday | `kickoff-v1`: Friday bold again; no extra text. |
| PK-05 | Split immediately before Friday | `paragraph-split-v1`: `Due` and bold `Friday` in separate paragraphs. |
| PK-06 | Join with previous paragraph | `kickoff-v1`: `Due Friday` in one paragraph with one space. |
| PK-07 | Undo join | Returns to `paragraph-split-v1`, retaining Friday's bold mark. |
| PK-08 | Redo join | Returns to `kickoff-v1`. |
| PK-14 | Try formatting while read-only | `remote-owner-v1` unchanged, no new history entry. |
| PK-15 | Async work targets an earlier document lifetime | Reject it; current `remote-owner-v1` and history remain unchanged. |

```text
kickoff-v1 → remove bold → friday-plain-v1 → apply bold → kickoff-v1
kickoff-v1 → split → paragraph-split-v1 → join → kickoff-v1
                     ↑                  │
                     └──── undo join ───┘  (redo returns right)
```

Download the [plain state](/concepts/project-kickoff-v1/friday-plain-v1.md) and [split state](/concepts/project-kickoff-v1/paragraph-split-v1.md) to compare without running an editor. These are authored expectations, not results generated by a replacement command engine. The split/join lesson deliberately restores the separating space; it does not define whitespace behavior for every API or selection affinity.

Selection ranges and stable anchors depend on the owning contract. Re-resolve an async target against the current document identity, lifetime and authority rather than keeping a raw numeric offset. A local undo should not erase another author's insertion. This linear lesson's local history entries do not qualify collaboration-aware undo or persistence of history across reopening.

Read the actual [command](@/docs/reference/api-commands.md), [selection](@/docs/reference/api-selection.md) and [event](@/docs/reference/api-events.md) declarations. Runnable command recipes and broader history evidence remain planned in the [command walkthrough entry](@/docs/reference/commands.md).

## Failure and recovery

A rejected operation must not be described as a successful edit. Preserve the latest content, report read-only or stale-target failure, and obtain a fresh selection/authorization before a new attempt. Never replay stale async work merely because text still looks similar. Selection, history and content expectations must all be checked independently.
