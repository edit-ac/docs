## Configuration and limits

```ts
// Fragment of the complete installed consumer; supply the existing host recovery options.
{ extensions: [References.configure({ host: localResolver }), SlashCommands.configure({ commands: localCommands })] }
```

**Options:** References.configure({host, triggers?}) requires the existing resolver or version1 permission/catalog/resolve/subscribe host. SlashCommands.configure({commands, literal?}) captures unique command IDs, labels and prepared callbacks.

**Dependencies and conflicts:** No declared feature conflicts. Prepared intents, permission and stale-range checks remain authoritative. Preserve original configured objects; serialization/spreading loses host bindings.

**Initial and deferred costs:** Required-input menu adapters; resolver/preparation is idle until explicit interaction. No socket/provider is supplied. These are loading boundaries, not benchmark numbers or a budget pass. The source manifest includes SDK-1.11/1.12 and EXT-1.20 receipts and their retained failures. A later mobile admission found disabled lightweight modules retained in the eager graph; its reduction remains owner work. Package archive bytes are not network transfer or startup measurements.

## Input, action and expected outcome

- **Input:** Due Friday in one editor and an unchanged sibling.
- **Action:** Open a local reference menu or Insert kickoff slash action with deterministic host callbacks.
- **Expected output:** Reference selection inserts the returned doc-42/Verified reference tuple; slash inserts bold Kickoff once. Undo restores Due Friday; sibling is unchanged.

The [complete checked example](@/docs/examples/extension-configurations.md) supplies initialization once, original source/downloads, independently expected outcomes and cleanup. Headings/lists reuse the [Project kickoff command examples](@/docs/examples/commands.md); this catalog introduces no second implementation.

## Serialization and import

Persist reference identity/label through the existing reference tuple, never callback closures or menu state. Unsafe URL insertion requires the separate validated URL recipe. See [format support](@/docs/guides/format-support.md) before conversion. Portable semantics and descriptors do not establish a native or terminal presenter. Only the exact local Chromium/production engine cases in the consumer receipt are newly observed here; other platforms remain planned/unqualified by this catalog.

## Accessibility, cancellation and teardown

Use existing keyboard menu navigation, labels and focus restoration. Trigger activation respects composition ownership. Closing/disposal or stale target aborts pending work; permission denial does not become document data. No document-open metadata fetch is implied. Async features remain editor-scoped. Closing a view releases subscriptions and captured resources; do not clear stored documents as teardown.

## Failure and recovery

Report admission errors before mounting, await readiness and expose optional feature failures. Preserve text, source and unknown payloads. Repair compatible assets/permissions and retry only the affected boundary. A local event does not prove a durable or remote save; use the [saving lifecycle](@/docs/reference/lifecycle.md).

## Migration and compatibility

Keep old low-level examples tied to their pinned versions. New facade code consumes the exact unpublished EXT-1.20 candidate; it does not make the pending shared-core merge a main release. [Extension overview](@/docs/extensions/_index.md), [custom extension status](@/docs/extensions/custom.md) and [Migrate to edit.ac](@/docs/migrate/_index.md) distinguish remaining work.
